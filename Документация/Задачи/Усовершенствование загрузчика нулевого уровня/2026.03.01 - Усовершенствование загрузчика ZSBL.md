# Усовершенствование загрузчика нулевого уровня (ZSBL)
## Краткое резюме для менеджмента

**Дата:** 2026.03.01

---

## Текущее состояние

### Что есть сейчас

Реализован базовый загрузчик ZSBL (Zero Stage Boot Loader), который:

✅ Инициализирует систему (регистры, стек)  
✅ Тестирует периферию (UART, GPIO, SRAM, HEX дисплей)  
✅ Проверяет наличие программы в SRAM по magic number (`0x52564D00`)  
✅ Передает управление на фиксированный адрес `0x02000004`  

### Ограничения текущей реализации

❌ **Один вариант загрузки** - только из SRAM по адресу `0x02000000`  
❌ **Нет выбора источника** - невозможно загрузить из SDRAM или других областей  
❌ **Нет конфигурации** - все параметры жестко закодированы  
❌ **Нет восстановления** - при ошибке система просто останавливается  
❌ **Нет диагностики** - минимальная информация об ошибках  
❌ **Нет обновления** - невозможно обновить загрузчик без перепрошивки FPGA  

---

## Проблема

Текущий загрузчик - это **"proof of concept"**, достаточный для базовой работы, но не обеспечивающий:

1. **Гибкость** - невозможно выбрать источник загрузки
2. **Надежность** - нет механизмов восстановления при ошибках
3. **Удобство разработки** - нет возможности загрузки через UART или другие интерфейсы
4. **Масштабируемость** - сложно добавить новые функции

### Типичные сценарии, которые не поддерживаются:

- Загрузка программы из SDRAM (большие программы)
- Загрузка через UART (без перепрошивки SRAM)
- Выбор между несколькими программами
- Загрузка с SD-карты
- Безопасная загрузка с проверкой подписи
- Обновление прошивки "на лету"

---

## Предлагаемое решение

### Концепция: Многоуровневый загрузчик с выбором источника

```
┌─────────────────────────────────────────────────────────────┐
│                    Усовершенствованный ZSBL                 │
├─────────────────────────────────────────────────────────────┤
│  1. Инициализация системы                                   │
│  2. Тестирование компонентов                                │
│  3. Чтение конфигурации загрузки                            │
│  4. Выбор источника загрузки (приоритеты)                   │
│     ├── SRAM (быстрая разработка)                           │
│     ├── SDRAM (большие программы)                           │
│     ├── UART (загрузка без перепрошивки)                    │
│     ├── SD Card (постоянное хранение)                       │
│     └── Fallback (резервная программа)                      │
│  5. Загрузка и верификация программы                        │
│  6. Передача управления                                     │
└─────────────────────────────────────────────────────────────┘
```

## Ключевые улучшения

### 1. Множественные источники загрузки

| Источник | Приоритет | Использование | Скорость |
|----------|-----------|---------------|----------|
| **SRAM** | 1 (высший) | Разработка, отладка | Мгновенно |
| **SDRAM** | 2 | Большие программы (>20KB) | Быстро |
| **UART** | 3 | Загрузка без JTAG | Медленно |
| **SD Card** | 4 | Постоянное хранение | Средне |
| **Fallback** | 5 (низший) | Аварийное восстановление | Мгновенно |

### 2. Конфигурация загрузки

**Способы конфигурации:**
- GPIO пины (DIP-переключатели на плате)
- Кнопки (KEY0-KEY3)
- Конфигурационная область в памяти
- Переменные окружения

**Примеры конфигураций:**
```
KEY0 нажата → Загрузка через UART
KEY1 нажата → Пропустить SRAM, загрузить из SDRAM
KEY2 нажата → Загрузить с SD-карты
KEY3 нажата → Войти в режим диагностики
```

### 3. Протокол загрузки через UART

```
Host (ПК)                    ZSBL (FPGA)
    │                            │
    │  "BOOT" (запрос загрузки)  │
    ├───────────────────────────>│
    │                            │
    │  "READY" (готов принять)   │
    │<───────────────────────────┤
    │                            │
    │  Размер программы (4 байта)│
    ├───────────────────────────>│
    │                            │
    │  Данные программы (N байт) │
    ├───────────────────────────>│
    │                            │
    │  CRC32 (4 байта)           │
    ├───────────────────────────>│
    │                            │
    │  "OK" или "ERROR"          │
    │<───────────────────────────┤
    │                            │
    │  Запуск программы          │
    │                            │
```

### 4. Расширенная диагностика

**Информация при загрузке:**
- Версия загрузчика
- Результаты тестов компонентов
- Обнаруженные источники загрузки
- Выбранный источник и причина
- Размер загруженной программы
- Контрольная сумма
- Время загрузки

**Коды ошибок:**
- `E01` - Нет валидной программы
- `E02` - Ошибка контрольной суммы
- `E03` - Таймаут загрузки
- `E04` - Недостаточно памяти
- `E05` - Ошибка чтения источника

### 5. Безопасность (опционально)

- Проверка CRC32/SHA256 загруженной программы
- Проверка цифровой подписи (для защищенных систем)
- Защита от переполнения буфера
- Ограничение времени загрузки

## Архитектура решения

### Структура памяти

```
┌──────────────────────────────────────────────────────────┐
│  ROM (0x00001000 - 0x00010FFF) - 64 KB                   │
│  ┌────────────────────────────────────────────────────┐  │
│  │  ZSBL Code (расширенный)                           │  │
│  │  • Инициализация                                   │  │
│  │  • Тесты                                           │  │
│  │  • Загрузчики (SRAM, SDRAM, UART, SD)              │  │
│  │  • Верификация                                     │  │
│  │  • Fallback программа (мини-монитор)               │  │
│  └────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────┐
│  OnChip RAM (0x00011000 - 0x00014FFF) - 16 KB            │
│  ┌────────────────────────────────────────────────────┐  │
│  │  Стек загрузчика (4 KB)                            │  │
│  │  Буфер загрузки (8 KB)                             │  │
│  │  Конфигурация (4 KB)                               │  │
│  └────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────┐
│  SRAM (0x02000000 - 0x02004FFF) - 2 MB                   │
│  Быстрая загрузка для разработки                         │
└──────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────┐
│  SDRAM (0x08000000 - 0x0FFFFFFF) - 128 MB                │
│  Большие программы, операционные системы                 │
└──────────────────────────────────────────────────────────┘
```

### Блок-схема загрузки

```
        START
          ↓
    Инициализация
          ↓
    Тесты периферии
          ↓
    Чтение конфигурации
    (GPIO, кнопки)
          ↓
    ┌─────────────┐
    │ Приоритет 1 │ → SRAM валидна? ──Да──> Загрузить из SRAM
    └─────────────┘         │
                           Нет
                            ↓
    ┌─────────────┐
    │ Приоритет 2 │ → SDRAM валидна? ──Да──> Загрузить из SDRAM
    └─────────────┘         │
                           Нет
                            ↓
    ┌─────────────┐
    │ Приоритет 3 │ → UART запрос? ──Да──> Загрузить через UART
    └─────────────┘         │
                           Нет
                            ↓
    ┌─────────────┐
    │ Приоритет 4 │ → SD Card валидна? ──Да──> Загрузить с SD
    └─────────────┘         │
                           Нет
                            ↓
    ┌─────────────┐
    │ Fallback    │ → Запустить мини-монитор
    └─────────────┘   (диагностика, UART shell)
```

## Варианты реализации

### Вариант 1: Минимальное улучшение (2-3 недели)

**Что добавляется:**
- Загрузка из SDRAM (в дополнение к SRAM)
- Выбор источника через GPIO/кнопки
- Улучшенная диагностика
- Fallback режим (простой монитор)

**Преимущества:**
- Быстрая реализация
- Минимальные изменения в коде
- Сразу полезный результат

**Недостатки:**
- Нет загрузки через UART
- Нет поддержки SD-карты
- Ограниченная гибкость

### Вариант 2: Средний уровень (4-6 недель)

**Что добавляется:**
- Все из Варианта 1
- Загрузка через UART (протокол)
- Проверка CRC32
- Конфигурационная система
- Утилита для загрузки с ПК

**Преимущества:**
- Удобство разработки (загрузка без JTAG)
- Надежность (проверка целостности)
- Гибкая конфигурация

**Недостатки:**
- Нет поддержки SD-карты
- Нет криптографической защиты

### Вариант 3: Полная реализация (8-10 недель)

**Что добавляется:**
- Все из Варианта 2
- Загрузка с SD-карты (FAT32)
- Проверка цифровой подписи (опционально)
- Обновление прошивки
- Интерактивный монитор (команды через UART)
- Поддержка нескольких программ (меню выбора)

**Преимущества:**
- Максимальная функциональность
- Промышленный уровень
- Основа для сложных систем

**Недостатки:**
- Длительная разработка
- Сложность реализации

## Бизнес-ценность

### Для исследования
- Возможность тестирования больших программ (>20KB)
- Быстрая итерация без перепрошивки
- Гибкость в выборе конфигурации

### Для образования
- Демонстрация работы многоуровневого загрузчика
- Изучение протоколов загрузки
- Практика работы с различными типами памяти

### Для дальнейшего развития
- Основа для загрузки операционных систем (Linux)
- Возможность обновления без JTAG
- Масштабируемая архитектура

## Риски и митигация

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| Превышение размера ROM (64KB) | Средняя | Высокое | Оптимизация кода, удаление неиспользуемых функций |
| Сложность протокола UART | Низкая | Среднее | Использование простого протокола с минимальными требованиями |
| Проблемы с SDRAM | Средняя | Среднее | Тщательное тестирование, fallback на SRAM |
| Увеличение времени загрузки | Низкая | Низкое | Оптимизация, параллельная проверка источников |
