# Реализация системы отладки процессора Wally
## Краткое резюме для менеджмента

---

## Проблема

Текущая реализация процессорной системы Wally на FPGA DE2-115 **не имеет полноценной системы отладки**. Это означает:

❌ Невозможно остановить выполнение программы  
❌ Невозможно просмотреть содержимое регистров и памяти во время выполнения  
❌ Невозможно установить точки останова  
❌ Невозможно использовать стандартные инструменты отладки (GDB)  

**Текущий метод:** Только наблюдение внутренних сигналов через Signal Tap (аналог осциллографа для FPGA) - крайне неудобно и ограничено.

---

## Решение

Реализовать систему отладки согласно стандарту **RISC-V External Debug Support v0.13**, которая включает:

### 1️⃣ Debug Transport Module (DTM)
**Что это:** Интерфейс JTAG для подключения отладчика к процессору  
**Аналогия:** USB-порт для подключения отладочного кабеля

### 2️⃣ Debug Module (DM)
**Что это:** Модуль управления отладкой процессора  
**Аналогия:** Диспетчер, который принимает команды от отладчика и управляет процессором

### 3️⃣ Модификации ядра процессора
**Что это:** Добавление специального режима отладки в процессор  
**Аналогия:** Добавление "режима паузы" в работающую программу

## Возможности после реализации

✅ **Интерактивная отладка** - остановка программы в любой момент  
✅ **Просмотр состояния** - чтение всех регистров и памяти  
✅ **Точки останова** - автоматическая остановка в нужных местах кода  
✅ **Пошаговое выполнение** - выполнение программы по одной инструкции  
✅ **Модификация данных** - изменение значений во время выполнения  
✅ **Стандартные инструменты** - использование GDB (как для обычных программ)

| Риск | Вероятность | Влияние | Митигация |

## Ожидаемый результат

После завершения проекта разработчик сможет:

```bash
# 1. Подключиться к процессору
$ openocd -f board/wally_de2-115.cfg

# 2. Запустить отладчик
$ riscv64-unknown-elf-gdb program.elf
(gdb) target remote localhost:3333

# 3. Загрузить программу
(gdb) load

# 4. Установить точку останова
(gdb) break main

# 5. Запустить программу
(gdb) continue

# 6. Просмотреть регистры
(gdb) info registers

# 7. Просмотреть память
(gdb) x/10x 0x80000000

# 8. Выполнить пошагово
(gdb) step
(gdb) next
```
