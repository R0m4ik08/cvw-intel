# План адаптации
 
Работа начинается с подготовительного этапа, на котором производится анализ исходного описания Wally и его адаптация под требования инструментария Quartus. 
 
Затем работа сосредотачивается на проектировании компьютерной системы в среде Platform Designer. Здесь решается задача интеграции процессорного ядра в экосистему платформы Quartus.
 
Следующий этап посвящен организации финального проекта и его интеграции с аппаратной платформой. Разработанная компьютерная система инкапсулируется в верхнеуровневый модуль, специфичный для платы DE2-115, где определяются все необходимые соединения с физическими портами и периферийными устройствами.
 
Завершающим этапом становится верификация работоспособности адаптированной системы.
  
# Подготовка исходников
 
## Краткое описание исходного репозитория
 
**CORE-V Wally ( **[**https://github.com/openhwgroup/cvw/tree/main**](https://github.com/openhwgroup/cvw/tree/main)** )** – это открытое аппаратное ядро RISC‑V с 5‑ступенчатым конвейером (pipeline), реализованное на SystemVerilog и нацеленное на образовательные и исследовательские задачи
 
Репозиторий содержит следующие ключевые директории и файлы: 
 
* **bin/**   
 – вспомогательные скрипты и утилиты для установки нужного ПО или обработки данных при сборке
 
* ***src/***   
 – исходный код ядра на SystemVerilog.
 
* **config/**   
 – файлы конфигурации ядра (набор параметров и опций сборки процессора).
 
* **fpga/**   
 – файлы поддержки для FPGA-плат (например, готовые образы для Arty A7, скрипты сборки).
 
* **examples/**   
 – примерные программы (на C и ассемблере), демонстрирующие работу ядра (например, «HelloWally»).
 
* **linux/**   
 – конфигурации и примеры загрузки Linux на ядре Wally (Buildroot, образы).
 
## Адаптация исходников для синтезатораQuartus
 
В теории можно было сразу взять исходный код из директории src и импортировать его в Quartus проект, но был рассмотрен иной подход. 
 
Он заключался в том, чтобы получить предварительно обработанные для одной из поддерживаемой платы файлы исходного описания и работать уже с ними. Этот вариант представился более предпочтительным в виду того, что файлы, описывающие архитектуру Wally, подразумевают не малое количество конфигураций для различных вариантов использования.
 
### Параметризация модулей
 
Одним из подходов обеспечения гибкой настройки процессорного ядра Wally является использование параметров для большинства модулей. Однако реализация в исходном проекте несмотря на то, что была удобной, оказалась несовместима с синтезатором в используемом окружении Quartus Prime.
 
В исходном проекте вместо того, чтобы передавать большой список параметров в модуль, передавался упакованный в структуру набор всех параметров текущей конфигурации, но как было сказано данная реализация вызывала ошибки синтезатора в Quartus.
 
После некоторых попыток обойти ограничения, было решено использовать стандартный подход передачи параметров.
 
### Замена блоков памяти
 
Изначально все FPGA, для которых адаптировано ядро Wally, принадлежат вендору Xilinx, и соответственно ip ядра блоков памяти для среды разработки Quartus не подойдут.
 
Были изучены типы используемых блоков памяти, и реализация соответствующих аналогов в Quartus благодаря специальному проводнику для создания IP ядер нужной конфигурации. 
 
Далее потребовалось скорректировать интерфейсы и добавить параметры для некоторых сигналов для имплементации в модулях ядра Wally
 
### Исправление синтаксических несоответствий

Одна из первых проблем, которая появилась при попытке собрать проект из файлов исходного описания – это проблема из-за реализации условного синтеза.
 
По аналогии с программированием, в языках описания аппаратуры используют подход, когда в зависимости от параметров в конечной архитектуре будут использоваться те или иный фрагменты описания.
 
Здесь и выявилась одна из проблем. В изначальном проекте подразумевалось использование синтезатора поддерживающего более новый стандарт языка System Verilog в котором использование управляющих конструкций, позволяющих реализовать условный синтез, не требуется их помещать в специальные generate блоки. А вот для синтезатора Quartus, который выдавал ошибки на упомянутые синтаксические конструкции и который нельзя поменять в рамках среды разработки, пришлось корректировать файлы с описанием ядра Wally.

# Разработка компьютерной системы (КС) в Platform Designer
 
## Обертка для процессорной системы (ПС)
 
Чтобы реализовать компьютерную систему в Platform Designer на основе процессорного ядра Wally, нужно создать соответствующий компонент, который можно будет интегрировать в среду разработки и использовать как основу.
 
В идеале, при создании компонента желательно добавить все файлы описания, но, вопреки тому, что основном проекте Quartus сборка проходит без ошибок, в редакторе компонентов Platform Designer возникают ошибки, решение которых требует очередного анализа и корректировки файлов описания ядра.
 
Чтобы не тратить на это время было решено использовать дополнительный модуль-обертку, который сохранял интересующие интерфейсы ПС Wally, но не требовал подключения System Verilog файлов реализации.
 
После создания данного модуля, нужно:  

* добавить его в редактор компонентов; 
* запустить анализ, чтобы среда разработки обнаружила параметры и выводы; 
* объединить выводы в интерфейсы.
 
## Мост между системной шиной ПС и стандартной шинойQuartus Avalon
 
Ядро использует шину AHB (Advanced High-performance Bus) из семейства AMBA (Advanced Microcontroller Bus Architecture) от ARM, но Quartus Prime и Platform Designer изначально ориентированы на шины Avalon, а не на AHB.
 
Это означает:
 
Нет нативной интеграции AHB в Platform Designer;
 
Большинство IP-блоков (UART, SDRAM Controller, GPIO) в Quartus —Avalon-MM совместимые.
 
В результате обозначенной проблемы были рассмотрены следующие варианты решения:
 
* ***Использовать AHB → Avalon адаптер:***   
 использовать доступный или реализовать самостоятельно
 
* ***Реализовать всю систему на AHB:***   
 найти или написать AHB Slave контроллеры для: SDRAM, SRAM и другой периферии.
 
* ***Модифицировать Wally под Avalon-MM:  ***переписать интерфейс Wally, заменив AHB на Avalon-MM Master
 
Как наиболее оптимальный был выбран первый вариант. *Использование адаптера AHB → Avalon *является наиболее удобным для интеграции ядра Wally в систему на базе Quartus. Этот подход обеспечивает совместимость с существующими IP-блоками, упрощает процесс проектирования, что значительно ускоряет разработку и повышает стабильность системы.
 
Диаграмма реализации выбранного решения:
 
    Wally (AHB Master)
    ↓
    [AHB → Avalon-MM Bridge]
    ↓
    Avalon-MM Slave
    ├── SDRAM Controller
    ├── SRAM Controller
    ├── UART
    └── GPIO
 
На практике не удалось найти готового IP ядра реализующего полноценную связь требуемых интерфейсов, но был обнаружен модуль External Bus to Avalon Bridge (EBAB), который предоставляет интерфейс для подключения периферийного устройства к коммутационной платформе Avalon в качестве ведущего устройства. 
 
External Bus интерфейс является более простыв в понимании, поэтому на было решено реализовать адаптер (AHB to EBAB), который с одной стороны будет иметь интерфейс AHB как ведомый, а с другой интерфейс непосредственно для IP ядра EBAB.
 
В конечном варианте схема, реализующая связь между системной шиной ПС  и стандартной  шиной Quartus Avalon, имеет вид: 
 
    Wally (AHB Master)
    ↓
    [AHB to External Master Peripheral bridge]
    ↓
    [External Bus to Avalon Bridge (EBAB)]
    ↓
    Avalon-MM Slave
